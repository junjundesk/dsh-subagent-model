# 使用教程

[返回首页](<../README.md>) · [版本兼容](<COMPATIBILITY.md>)

## 1. 安装前检查

1. 运行 `dsh --version`。历史真实宿主验证（1.1.0，非完整浏览器 E2E）为 **0.2.2-alpha.2**；1.1.1 起清单也接纳 `0.2.1-rc.5`（静态比对 + 模型选择适配 + 组件级路由验证 22/22 PASS，真实 LLM / 浏览器 E2E 未做，见 [版本兼容](<COMPATIBILITY.md>)）。
2. 使用挂载了原生模型、设置、凭据服务的 DSH Web profile。
3. 通过固定标签 `github:junjundesk/dsh-subagent-model#v1.1.1` 或 [v1.1.1 Release](<https://github.com/junjundesk/dsh-subagent-model/releases/tag/v1.1.1>) 的编译包安装并启用，重启目标 profile 并刷新浏览器（详见 [README 安装章节](<../README.md>)）。
4. 在 **设置 → 子代理模型** 打开；插件详情页也有相同面板。

安装只注册功能，默认“跟随 DSH 原有行为”，不会帮你自动挑选或切换付费模型。

## 2. 选择已有分组和模型

1. 在 **模型选择** 中勾选“使用指定模型”。
2. 从“分组 / 服务商”选择已经在 DSH 配置的分组。
3. 选择模型。这里使用的是该分组实际提供的模型 ID。
4. 选择推理强度：
   - **自动（模型默认）**：由目标模型的 DSH 适配器决定；不沿用其他模型的强度。
   - **指定强度**：只能选择当前模型目录声明的值。
   - 如果没有可选强度，下拉框不可编辑是正常情况，不代表模型不可用。
5. 点击“保存设置”，看到保存成功提示后，再新建子代理。

**切换分组或模型会清空草稿中的旧强度**，避免把 A 模型的参数误发给 B 模型。“当前已保存”显示生效配置，草稿未保存前不会应用。

如果在另一标签页修改过设置，当前页保存可能收到修订冲突。点击“重新载入”后重选；重新载入会丢弃未保存的选择。

## 3. 添加自定义 API

展开“添加自定义 API”，填写下表。

| 字段 | 怎么填写 |
| --- | --- |
| 分组标识 | 1–40 位小写字母、数字或连字符，开头必须是字母/数字，例如 `my-chat` |
| 分组显示名称 | 自己容易辨认的名称，例如“我的网关” |
| 请求类型 | 按服务商文档选择 Chat、Responses 或 Claude，不依据模型名字猜测 |
| API 基础地址 | 服务商要求的基础 URL，不能把密钥放在 URL 用户信息、查询参数或片段中 |
| 模型 ID | 接口接收的精确 ID，不是服务商控制台里的营销名称 |
| API 密钥 | 在密码输入框中输入真实密钥，不要在聊天、Issue 或 GitHub 配置中填写 |
| 上下文窗口 | 真实模型容量；表单默认 128000 只是初始值，不代表模型支持 |
| 最大输出 | 正整数，不得超过上下文窗口；初始值为 8192，请按服务商限制调整 |
| 推理强度能力 | 只声明服务商明确支持的值；未知时全部不选 |

### 地址示例

```text
Chat:      https://gateway.example.com/v1
Responses: https://gateway.example.com/v1
Claude:    https://api.anthropic.com
```

前两个是占位域名，不能直接当可用服务。第三个地址是否可用仍取决于你的账户权限和网络。

插件会去掉粘贴地址末尾的 `/chat/completions`、`/responses` 或 `/messages`；Claude 还会去掉末尾 `/v1`，由原生 SDK 拼接路径。特殊代理请以其文档为准。

### 保存顺序

1. 点击“添加 API 分组”。
2. 插件先把密钥保存到 DSH 凭据服务中的独立随机引用，再写入原生适配器分组。
3. 添加后检查实时模型目录与目录归属，确认分组激活。
4. 上方模型选择区域填入新分组/模型草稿。
5. **确认推理强度并点击“保存设置”**，才会把它设为子代理固定模型。

分组 ID 自动加上 `dsh-subagent-` 前缀；例如 `my-chat` 最终是 `dsh-subagent-my-chat`。已有同名分组不会被覆盖。要编辑已有分组，请转到 **设置 → 模型**，不是重复添加。

### 强度能力不是自动探测

- 可选声明：`off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`。
- 值会交给 DSH 原生适配器；不同服务商的协议兼容能力由该适配器决定。
- 全不选表示不启用该模型的推理强度控制。
- 不能只选 `off`：声明强度时至少要有一个非 `off` 档位。
- `off` 映射为不发送强度字段，**不保证网关实际关闭思考**。
- 当前表单将自定义模型声明为文本输入，不自动声明视觉能力。
- 成功保存不等于做过联网推理测试，也不保证第三方支持 DSH 所需的工具调用。

## 4. 怎样确认真正生效

1. 先在面板确认“当前已保存”的分组、模型和强度。
2. 要求主代理**新建一个本地子代理**执行简单任务。
3. 不要给主代理额外指定不同的 provider/model 参数，以免先触发原生路由授权限制。
4. 查看 DSH 的子代理详情或请求路由信息（如果当前界面提供）。只读工具 `dsh_subagent_model` 的 `status` 能检查保存值，但不能单独证明某次请求已经使用该模型。

以下情况不会按新设置换模型：

- 给已经创建的子代理发后续消息；
- 冷恢复旧子代理；
- 外部 Codex CLI、Claude Code CLI、ACP 等独立进程；
- 主代理自身继续对话。

固定模型在创建子代理时写入官方 `model/selection` 事件。插件没有劫持/重写主代理请求。

## 5. 恢复默认、升级和卸载

**恢复默认**：选“跟随 DSH 原有行为”并保存。这会停止插件覆盖，不会强制所有子代理都继承主代理；原工具自己的默认模型设置仍然有效。

**升级**：先记下自己的固定模型设置，阅读 [更新记录](<../CHANGELOG.md>) 和 [兼容说明](<COMPATIBILITY.md>)。通过插件管理器安装指定新标签；若提示已安装不可覆盖，按提示先卸载旧包再安装。重启/刷新后检查设置，必要时重新选择。

**卸载**：从插件页卸载本插件。不主动删除原生适配器中的自定义分组和密钥，不删除会话，也不停止已运行子代理。

## 6. 常见问题

### `cannot get property "remote.settings" without inject`

这是 1.0.0 的 Client 依赖声明缺失，**1.0.1 已修复**。确认安装的是 1.0.1 或更新版本（当前为 1.1.1），关闭设置后重新打开；旧缓存可强制刷新，仍不更新时按安装器提示重启 profile。

### `active teammate "<uuid>" not found`

这是 DSH 内置 Agent Teams 的 `send_message` / `interrupt_agent` 参数问题：`target` 必须是 `list_agents` 返回的队友名字（例如 `lead`），不是子代理/会话 UUID。

从 1.1.0 起，插件会在调用前校验：把 UUID 识别出来并提示对应队友名，或列出合法名字，避免原始堆栈。如果仍看到原始错误，先确认插件已升级并重启；然后调用 `list_agents`，使用返回的 `target`（不是 `id`）重试。给子代理发消息应使用子代理控制工具的 `agent_id` 形式，不要用 Team 的 `send_message`。

### 找不到设置入口

确认安装到正在使用的 profile，插件已启用，并且该 profile 是具备原生服务的 Web profile。纯 headless/TUI 没有本插件面板。

### 在 DSH 0.2.1-rc.5 上使用固定模型（内部接口回退）

`0.2.1-rc.5` 没有 `agent.model`，1.1.1 会 feature-detect 回退到 `sessionController.agents.selectForNextRequest`。这是 DSH **内部/private 接口**（非公共契约，后续版本可能变更或移除）：

- 只要宿主提供 `agent.model.select()`（如 `0.2.2-alpha.2`），插件始终优先走该公开路径；
- **不会调用公共 `selectModel`**（它改部署默认模型且拒绝子代理请求），任何声称需要它的报错都应反馈给插件；
- 路由校验失败时子代理**创建直接失败**并给出原因，不会静默用错模型；
- 首次在 rc.5 启用后，请新建一个本地子代理跑最小任务，核对日志/会话中实际请求的 provider/model/强度，再决定是否长期启用。

### 显式选择子代理模型被 DSH 拒绝

插件不修改原生模型授权白名单。请让主代理省略 provider/model/effort，依赖本插件固定设置；如果确实需要模型自行选路由，应通过 DSH 原生授权界面管理，不要直接改会话日志。

### 分组保存失败，但提示密钥已保存

两步不是原子事务。不要重复输入/创建多个密钥。按提示保留凭据引用，在 DSH 模型设置里检查分组状态后再继续。插件不会自动删除已经成功保存的密钥。

### 分组已保存，但激活验证失败

配置已经提交，不要当作“完全没保存”重复添加。重新载入，检查原生模型页的注册错误、重复路由和模型能力声明。

### `401`、无余额、超时、工具调用报错

这些属于真实服务商/网络/协议兼容问题。确认 URL、密钥、模型 ID、接口类型以及 token 和 reasoning 限制。不要仅凭模型名称判断该用 Chat 还是 Responses。

### 安装时 GitHub 连接失败

GitHub 安装需要网络可达；可以从发布页下载安装包再交给 DSH 管理器。profile 中其他 GitHub 依赖也可能在依赖解析时导致安装失败；换 npm 镜像并不一定能修复 GitHub 网络问题。

## 7. 安全提醒

- 自定义端点会收到子任务内容和工具结果；fork 子代理还会发送继承的对话。
- 请使用可信 HTTPS 地址；HTTP 会明文传输网络数据。
- DSH 本地凭据服务不是隔离同系统账户进程的保险箱。
- 报告问题时只提供脱敏错误、版本和复现步骤，不上传密钥、`.env`、profile 文件或完整会话日志。
